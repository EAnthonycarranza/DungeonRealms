# Maps (Tiled)

Each region is a Tiled isometric map in `assets/tiles/`, named by the
region's `map` field in `world.json`. Goblinwood is
`assets/tiles/goblinwood.tmx`: 76×76 tiles of 128×64 px. It is generated by
`tool/maps/generate_goblinwood.dart`, but it is a normal Tiled file and can be
opened and edited in [Tiled](https://www.mapeditor.org/).

The game parses the map in `RegionMap` (`lib/game/world/region_map.dart`).
Flame's `flame_tiled` draws the tile layers; props and characters are drawn
by the game so they can be depth-sorted together.

## Coordinates

- World space is in tiles. A Tiled isometric object at pixel position
  `(x, y)` is at world `(x / 64, y / 64)` (64 = tile height).
- Tile objects (props) are anchored at the bottom of their image. Each prop
  tile's `anchorY` property says how far above the image bottom its ground
  centre is, so the game places its feet at
  `(x / 64 − anchorY / 64, y / 64 − anchorY / 64)`.
- Screen position: `((x − y)·64 + H·64, (x + y)·32)` with `H` the map
  height. See [ARCHITECTURE.md](../../ARCHITECTURE.md#coordinates).

## Layers

| Layer | Kind | Contents |
| --- | --- | --- |
| `ground` | tiles | Terrain from `terrain.tsx` (grass, dirt, cobble, forest, water) |
| `decor` | tiles | Flat decals from `decor.tsx` (flowers, leaves, pebbles, tracks) |
| `props` | objects | Scenery tile objects from `props.tsx` (trees, houses, rocks, fences) |
| `interactives` | objects | Prop tiles the hero can use (see below) |
| `gameplay` | objects | Points and zones (see below) |

The map has a `region` property with the region id.

### Terrain

`terrain.tsx` holds 88 corner-based Wang tiles. Each tile has a `corners`
property (`top,right,bottom,left` vertex terrains) that the game reads to
know the terrain anywhere on the map. Terrains marked
`"walkable": false` in `world.json` (forest, water) block movement; the
boundary between walkable and blocked terrain is smooth because walkability
is blended between corners. Allowed neighbours are grass with anything,
cobble with dirt.

### Props

`props.tsx` is an image collection (one PNG per prop in
`assets/tiles/props/`). Tile properties:

| Property | Meaning |
| --- | --- |
| `name` | Prop id used by code and the generator |
| `anchorY` | Image pixels from the bottom up to the ground centre |
| `collision` | Collision circle radius in tiles (0 = none) |
| `footprint` | `"w,h"` collision box in tiles, centred on the ground point |
| `wall` | `u` or `v`: a one-tile wall segment along that world axis (fences) |
| `walkable` | `"w,h"` area that is walkable even over blocked terrain (the bridge) |
| `layer` | `sorted` (default, depth-sorted) or `ground` (flat, under characters) |
| `emitter` | `fire`: the game adds a flame, embers and smoke |

Tall props fade out when they would hide the hero.

## Interactives

Tile objects in the `interactives` layer, by object `type`:

| Type | Properties | Behavior |
| --- | --- | --- |
| `resource` | `node`: resource id (`world.json`) | Gather with a Day Job; shows its `depletedProp` until it respawns |
| `chest` | `loot`: loot table; `level`: minimum item level | Opens once per hero. The object name is the `open` quest target |
| `waypoint` | `waypoint`: waypoint id from the region | Discover, travel, refill potions; a sanctuary for 5 tiles around it |
| `boss_gate` | `boss`: boss id | Invisible and open until that boss's fight starts, then blocks the way |

Chests use the `chest_open` prop when opened, and waypoints switch to
`waypoint_stone_active` when discovered.

## Gameplay objects

Shapes in the `gameplay` layer (rectangles, ellipses or points), by `type`:

| Type | Shape | Properties | Behavior |
| --- | --- | --- | --- |
| `player_start` | point | | Where a brand-new hero appears |
| `npc` | point | `npc`: NPC id | Places the NPC |
| `spawn` | zone | `pack`, `level`, `respawn` (s, default 60) | Keeps one pack alive: `respawn` seconds after it's wiped, it returns once the hero is 15+ tiles away |
| `event` | zone | | Named zone for a public event (`world.json` event `zone`) |
| `boss_arena` | ellipse | `boss`, `level` | The boss fight starts when the hero gets near its centre (within 36% of its width); gates close |
| `boss_spawn` | point | `boss` | Where the boss stands |
| `trigger` | zone | `discover`: id | Entering it completes `discover` quest objectives |
| `area` | zone | `title`, `subtitle` | Shows an area banner on entry (and names the current area) |

`test/game/game_smoke_test.dart` checks that every object points at real
content (packs, NPCs, resources, loot tables, waypoints, bosses, event zones,
quest targets), and that the boss arena is sealed while its gate is up.

## The Goblinwood generator

```bash
dart run tool/maps/generate_goblinwood.dart
```

It is deterministic (fixed seed), so the same code always writes the same
map. Steps:

1. **Layout**: places (Buckleburg, the crossroads, the camp, the bridge, the
   hollow, the arena) and roads, a stream and trails as splines.
2. **Terrain**: picks a terrain for every tile corner (forest outside the
   open areas and around the arena, water for the stream and pond, dirt
   roads, a cobble plaza), fixes invalid corner combinations, then picks the
   matching Wang tile.
3. **Decor**: flowers, leaves, tracks and pebbles by terrain.
4. **Set pieces**: town buildings, NPC spots, the camp, the hollow, the arena
   ring, waypoints, the bridge, resources and chests.
5. **Forests and scatter**: dense trees on forest terrain, sparse trees,
   bushes and rocks in the open, avoiding set pieces and roads.
6. **Gameplay**: spawn zones, areas, triggers, the event zone, the boss
   arena.

To change Goblinwood, edit the generator and rerun it, then check the result
with `ART=mappreview flutter test tool/art/generate_art_test.dart`
(`build/art_preview/goblinwood_map.png`) and the tests. If you'd rather
hand-edit the TMX in Tiled from now on, stop running the generator (or port
your edits into it); a rerun overwrites the file.

## Adding a region

1. Make the map, by hand in Tiled or with a generator like Goblinwood's,
   using the same tilesets and object conventions.
2. Add the region to `world.json` (`map`, `waypoints`, `startWaypoint`,
   flavor) and set `playable: true`.
3. Add its enemies, packs, quests, NPCs, loot tables and events.
4. Run the tests; the map test validates every reference.
